iCell Suite: iCellR2 · iCellPy · SODA · bash CLI · SODA viewer · SODA ≈ BAM for single-cell — portable on-disk archive · Why fast: disk streaming · virtual · lazy scale · HVG cache · Viewer on Win / Mac / Linux

Overview

iCellR2 (R) and iCellPy (Python) share one design: familiar analysis verbs (load → QC → PCA → UMAP), but a thin live handle — all data stays in SODA (single omics data archive). No giant matrices, lists, .rds, or pickles in RAM; the archive is the project. The six highlights below are the design.

SODA is a folder of portable files (JSON · HDF5 · TSV · Parquet) — like BAM for alignments: a tool-neutral layout, not a language-private object. Mid-pipeline handoff is a path; logs and benchmarks travel with the archive.

Because the project is a folder, the same verbs can run from a bwa/samtools-style bash CLI (iCellR2 make.obj …) with R in the background. Packaging atlas-scale sc analysis to the archive, not an in-memory object, is the unit of work across R, Python, viewer, and bash.

SODA & viewer

SODA (single omics data archive) is a folder of portable files (JSON · HDF5 · TSV · Parquet): assays, reductions, metadata, logs, and benchmarks. Like BAM for alignments, it is a tool-neutral layout, not a language-private object.

Why it matters
  • .rds / AnnData h5ad lock you into one ecosystem and often into RAM.
  • Mid-pipeline handoff should be a path, not an object conversion.
  • Progress, command history, and timings belong with the data so runs are auditable.
What you get
  • Start in iCellR2, continue in iCellPy (or reverse) on the same *.soda/.
  • Browse UMAP / clusters in the Java SODA viewer without re-exporting.
  • iCellR2.log, benchmark.txt, and session summaries travel with the archive.
Bash CLI · same archive

SODA makes a shell front-end natural: each iCellR2 <command> is a short R process that reads/writes a folder path. That is a product leap for single-cell (HPC scripts without learning and monitoring an R session). 

iCellR2 make.obj -input raw/PBMC_2700 -sample.id pbmc -out.dir PBMC -project_name PBMC_project
iCellR2 qc.stats -soda PBMC.soda
iCellR2 refresh -soda PBMC.soda

Tutorials · Small data

Small data · ~2.7K cells · four tracks
End-to-end small PBMC demo across four tracks (R, R bash, Python, Python bash). Each step explains what the function does, whether it materializes data, and where files land in SODA (with table headers).

Big picture

Public input is the classic 10x Genomics PBMC 3K dataset (filtered gene-barcode matrices). For this tutorial it was split into four labeled samples — WT, KO, Ctrl, KD as separate .h5 files under 1_small_data/data/ — so you can practice a multi-sample workflow (aggregation + conditions), not just a single matrix. Script: 1_small_data/iCellR2/test.R. The durable archive is PBMC.soda/. Pipeline below:
load10x ×4→ aggregate→ make.obj / SODA→ QC + filter→ norm→ gene model→ PCA · UMAP · cluster→ pseudotime→ markers · DE · plots

01 · Load each sample · load10x

load10x reads one 10x Genomics source — either a Cell Ranger outs directory (matrix.mtx + barcodes/features) or a native .h5 — and returns a sample handle. With output = "virtual" (recommended), HDF5 inputs keep a pointer to the original file (no matrix copy into RAM); MTX directories are converted to a modern 10x HDF5 first. That is why virtual is good for large or multi-sample projects: memory stays thin and each sample keeps its own file identity. Virtual is still temporary until make.obj — the self-contained SODA copy is created there (by default copy.raw = TRUE copies counts into the archive). Useful options: input.format (auto / 10x_h5 / 10x_dir), sample.id (becomes the condition label), output = "data.frame" if you truly want an in-memory matrix.
library(iCellR2)

wt <- load10x("../data/WT.h5", input.format = "10x_h5",
              sample.id = "WT", output = "virtual", overwrite = TRUE)
ko <- load10x("../data/KO.h5", input.format = "10x_h5",
              sample.id = "KO", output = "virtual", overwrite = TRUE)
ctrl <- load10x("../data/Ctrl.h5", input.format = "10x_h5",
                sample.id = "Ctrl", output = "virtual", overwrite = TRUE)
kd <- load10x("../data/KD.h5", input.format = "10x_h5",
              sample.id = "KD", output = "virtual", overwrite = TRUE)

02 · Combine samples · data.aggregation

data.aggregation is only needed when you have more than one sample. A single load10x result can go straight into make.obj. With multiple samples it builds a logical aggregation: sample handles, barcode maps, and condition labels — no merged mega-matrix in RAM. Prefer unique sample.ids in each load10x call so conditions (WT / KO / Ctrl / KD) are set automatically. This step still does not create a SODA; it only stages inputs for make.obj.
agg <- data.aggregation(
  samples = list(WT = wt, KO = ko, Ctrl = ctrl, KD = kd),
  output = "virtual"
)

03 · Create the archive · make.obj

make.obj creates the project: a thin handle-only object plus the on-disk SODA (Single Omics Data Archive) at out.dir.soda (here PBMC.soda/). Assay matrices are not kept inside the S4 object — they live under modalities/rna/assays/counts/. For native 10x HDF5, default copy.raw = TRUE copies each sample’s .h5 into the archive so the project is portable; set copy.raw = FALSE to store pointers only (saves disk, less self-contained). Also writes metadata/cell_data.tsv, sample/feature tables, soda.json, and project info. This is the moment virtual staging becomes a real analysis archive.
obj <- make.obj(
  x = agg,
  out.dir = "PBMC",
  project_name = "PBMC_project",

HTO demux · iCellR2

Load a multimodal / TotalSeq library (or an object that already has HTO rows in counts). hto.anno finds Antibody Capture / TotalSeq features, streams those rows only, and annotates cells.

library(iCellR2)

## Option A · classic (annotate → demux / split)
# MyHTOs <- counts[grep("TotalSeq|Hashtag|CMO", rownames(counts)), ]
anno <- hto.anno(
  hto.data = MyHTOs,
  cov.thr = 10,
  assignment.thr = 80,
  out.name = "HTOs_annotated_HSThigh",
  plot = TRUE,
  plot.format = "pdf"
)
# filter + write RNAs__/ (or .h5)
anno2 <- hto.demux(
  anno = anno,
  rna.data = MyRNAs,
  min.percent = 70,
  out.format = "10x_dir"   # or "tenx_h5"
)

## Option B · SODA object (preferred)
obj <- open.soda("project.soda/")
obj <- hto.anno(obj, cov.thr = 3, assignment.thr = 80, plot = TRUE, plot.format = "pdf")
table(obj@cell_data$hto_assignment)

obj <- hto.demux(
  obj,
  min.percent = 70,
  keep.good.only = TRUE,
  subset.cells = TRUE,
  out.format = "tenx_h5"
)
obj <- norm.data(obj)
obj <- run.pca(obj)
